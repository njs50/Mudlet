<task type="auto">
  <name>Task 1: Fix Hunspell leak and remove redundant mpTimerReplay delete</name>
  <files>src/mudlet.cpp, src/mudlet.h</files>
  <read_first>
    - src/mudlet.cpp (lines 4755-4770 for destructor; lines 6360-6410 for prepareSharedDictionary)
    - src/mudlet.h (line 599 for mpHunspell_sharedDictionary declaration; line 35 for memory include)
  </read_first>
  <action>
In src/mudlet.cpp, in the destructor `mudlet::~mudlet()` starting at line 4755:

1. **Remove the redundant mpTimerReplay delete (lines 4760-4761).** Delete these two lines:
   ```cpp
   delete (mpTimerReplay);
   mpTimerReplay = nullptr;
   ```
   Rationale: mpTimerReplay is a `QPointer<QTimer>` created with `new QTimer(this)` at line 4976. Qt's parent-child system will delete it when `mudlet` (the parent) is destroyed. The QPointer self-nulls after destruction. Per D-04, Qt-derived classes stay on Qt parent-child.

2. **Fix the Hunspell leak (line 4763-4766).** Change:
   ```cpp
   if (mpHunspell_sharedDictionary) {
       saveDictionary(getMudletPath(enums::mainDataItemPath, qsl("mudlet")), mWordSet_shared);
       mpHunspell_sharedDictionary = nullptr;
   }
   ```
   To:
   ```cpp
   if (mpHunspell_sharedDictionary) {
       saveDictionary(getMudletPath(enums::mainDataItemPath, qsl("mudlet")), mWordSet_shared);
       Hunspell_destroy(mpHunspell_sharedDictionary);
       mpHunspell_sharedDictionary = nullptr;
   }
   ```
   This adds the missing `Hunspell_destroy()` call before nulling the pointer. The `Hunspell_destroy` function is available from `<hunspell/hunspell.h>` which is already included in mudlet.h.

Note: Do NOT modify the `mpHunspell_sharedDictionary` member type in mudlet.h. Keep it as `Hunhandle*`. The singleton is returned to multiple TMainConsole instances as a non-owning raw pointer, so the ownership stays simple: mudlet creates it, mudlet destroys it.

Note: Do NOT touch `TMainConsole::mpHunspell_shared` -- it is a non-owning observer pointer to the singleton owned by mudlet. TMainConsole must NOT call Hunspell_destroy on it.

  <action>
In src/TMap.h:

1. **Add `#include <memory>`** in the STL includes section (after line 42 `#include <optional>`). The header does not currently include it.

2. **Change the member declaration at line 206** from:
   ```cpp
   TRoomDB* mpRoomDB = nullptr;
   ```
   To:
   ```cpp
   std::unique_ptr<TRoomDB> mpRoomDB;
   ```
   The forward declaration `class TRoomDB;` at line 66 is sufficient because `~TMap()` is declared out-of-line (defined in TMap.cpp where TRoomDB.h is included). Per D-05, use standard `std::unique_ptr<T>` with no custom deleter since TRoomDB is a plain C++ class with a normal destructor.

In src/TMap.cpp:

3. **Change the ctor initializer at line 85** from:
   ```cpp
   , mpRoomDB(new TRoomDB(this))
   ```
   To:
   ```cpp
   , mpRoomDB(std::make_unique<TRoomDB>(this))
   ```

4. **Remove the explicit delete at line 106** in the destructor:
   ```cpp
   delete mpRoomDB;  // DELETE THIS ENTIRE LINE
   ```
   The unique_ptr destructor handles it automatically.

5. **All call sites using `mpRoomDB->` remain unchanged** because `unique_ptr::operator->()` works identically to raw pointer `->`.
