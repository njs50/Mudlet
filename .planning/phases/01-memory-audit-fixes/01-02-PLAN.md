   With:
   ```cpp
   auto pCondition = std::make_unique<TMatchState>(mPatterns.size(), mConditionLineDelta);

   ```
   Then update ALL subsequent uses of `pCondition` in that function to use `pConditionRaw` instead. Specifically, lines after 533 that reference `pCondition->multiCaptureList`, `pCondition->multiCapturePosList`, `pCondition->nameCaptures` should use `pConditionRaw->` instead. (Per Pitfall 4 in the research: capture raw pointer for key, transfer ownership to unique_ptr for value.)

4. **Update all iteration loops that access `matchStatePair.second`.** In the following locations, change `matchStatePair.second->` to `matchStatePair.second.get()->` OR simply `matchStatePair.second->` (unique_ptr::operator-> works directly). Actually, `std::unique_ptr::operator->()` returns the raw pointer, so `matchStatePair.second->member` works without `.get()`. **No change needed for `->` access patterns.** BUT any place that reads `matchStatePair.second` as a raw pointer value (e.g., passing it to a function expecting `TMatchState*`) must use `.get()`.

   Check these iteration sites:
   - Line ~548: `for (auto& matchStatePair : mConditionMap)` — uses `matchStatePair.second->` (no change needed)
   - Line ~787: same pattern (no change needed)
   - Line ~957: same pattern (no change needed)
   - Line ~1026: same pattern (no change needed)

5. **Update the match removal block (lines 1067-1072).** Replace:
   ```cpp
   if (mConditionMap.find(matchState) != mConditionMap.end()) {
       delete mConditionMap[matchState];
       if (mudlet::smDebugMode) {
           TDebug(Qt::darkBlue, Qt::black) << "removing condition from condition table.\n" >> mpHost;
       }
       mConditionMap.erase(matchState);
   }
   ```
   With:
   ```cpp
   if (mConditionMap.find(matchState) != mConditionMap.end()) {
       if (mudlet::smDebugMode) {
           TDebug(Qt::darkBlue, Qt::black) << "removing condition from condition table.\n" >> mpHost;
       }
       mConditionMap.erase(matchState);
   }
   ```
   The `delete` is removed — `mConditionMap.erase(matchState)` destroys the unique_ptr value, which automatically deletes the TMatchState object. The debug output is moved before erase so it runs while the state is still valid (matchState pointer is a local copy in the removeList, not the map value — safe to use as key after erase).

6. **Check `mConditionMap.size()` calls** — these are size_t returns, no change needed.
